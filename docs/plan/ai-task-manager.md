# AIタスク管理システム(AI上司) 設計ドラフト

> 「勝手にタスク管理ができる仕組みが欲しい」— 2026-04-15 議事録

## 1. 目的

やることが多すぎて全体像が追いつかない状態を解消する。人間がタスクを整形・更新する作業自体を無くし、AIが横串で把握・評価・催促する。

## 2. 課題(議事録より)

- 誰が何をどこまでやっているか不明確
- メール・Teams・口頭で突発的に発生するタスクを一元管理できない
- タスク管理自体が新たな作業になり、続かない
- 没頭してしまい「今日何やったか」を忘れる
- 営業・開発・総務(Pマーク等)・インフラ移管が並行し、先の先まで計画できない

## 3. コンセプト: AI上司

1. **入力はどこからでも** — 音声、Teams、メール、Git活動、議事録テキスト。
2. **横串で関連付け** — 「ソフトバンク/ベルパークとのやり取り」=「営業タスク」=「ダッシュボードに投稿される予定」の依存関係を自動で結ぶ。
3. **継続評価** — 各タスクに期限と完了条件(Definition of Done)を持たせ、日次で未達・停滞を指摘。
4. **報告は声で** — 没頭を妨げない。右下トレイに向かって喋るとAIが構造化して記録。

## 4. スコープ(最小構成)

| レイヤ | 役割 | 最小実装 |
|---|---|---|
| 入力 | 音声/テキスト受付 | Mac常駐トレイアプリ(別ドキュメント参照) |
| 記憶 | タスク・契約・担当者の構造化DB | 6箱(後述)に紐付くJSON/SQLite |
| 連携 | Git / Teams / メール / カレンダー | Git(まず)→ メール → Teams の順 |
| 出力 | 日次サマリ / 週次レビュー / アラート | 朝のブリーフィング + 18:00会議向け共有 |

## 5. 6つの箱(ドメイン)

議事録で言及された「6個の箱」を一次ドメインに採用。

1. **PC資産管理** — レンタルPC返却判断、リソース配分、コストカット記録。
2. **ドコモMLP(通話録音)** — ベンチマーク、契約条件調査、スモールスタートか全面移行か判断。
3. **コンプライアンス** — Pマーク(6月監査)、職業紹介事業報告書(4/30)、労働者派遣事業報告書(4/30)、スキル化。
4. **インフラ統合** — Linux Web01/02への移管、RPA廃止、勤怠・契約のバックアップ、セキュリティ診断。
5. **契約・請求管理** — BP請求↔クライアント請求の突合、作業完了報告書の自動担当者入力、オペレーション文書化。
6. **ダッシュボード** — BAT統合、返信率、ギガカミ参照、ドコモ通録データ取り込み。

各箱の詳細タスクは `docs/tasks/` 以下にMarkdownで分割する。

## 6. AI上司の最低限の振る舞い

- **毎朝(09:00)** — 各箱の停滞タスクと当日の締切を一覧化し、音声で読み上げ。
- **会話後(随時)** — トレイアプリへの発話から、新規タスク/更新/完了を抽出してDBに書込。
- **毎晩(22:00)** — Git/Teams/メールのアクティビティを横断評価し、「言ったけど動いてない」タスクを検出。
- **18:00会議前** — その日の進捗をサマリー化。

## 7. 段階的な実装ロードマップ

- **初期(今月)** — トレイアプリ試作+6箱のMarkdown台帳。手動で回しつつ音声入力を慣らす。
- **中期(5月〜)** — Git/Teams/メール連携。LinuxサーバへのRPA移管と同時に、タスクDBをWeb01に同居。
- **終了(6月以降)** — Pマーク監査対応完了、全オペレーションをスキル化しAIが自走。

## 8. 開かれた論点

- タスクDBの置き場(Notion vs 自前SQLite)
- 音声入力の文字起こしモデル(ローカル vs API)
- Teams/メール連携時のPマーク的な情報取り扱い
